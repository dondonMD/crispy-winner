## Frozen synthetic load protocol

`validate_evidence_load.py` runs the actual consumer loop, periodic analysis/evaluation/retention and observational adapter at exactly 250 configured candidates. Each candidate starts with 200 explicitly synthetic warm events across 180 seconds, including distinct price paths to avoid unrealistically sharing every volatility cache entry. Timed primary load is 15 trades/s for 210 seconds (comparable to the prior smoke's ~14/s), plus 0.7 recovery arrivals/s and a monitoring stand-in RPC every five seconds. A separate 50 trades/s, 60-second stress envelope is planned. Normalized synthetic inputs do not exercise live decoding and are never reported as market evidence or real CURRENT.

All HTTP uses an in-process MockTransport with 150ms response delay and the production shared provider limiter. No provider transport/enrichment task is started. Recovery uses complete synthetic non-Pump transactions, preserving the real classifier and 2-worker/32-pending/45s/3-attempt bounds. Monitoring stand-in requests demonstrate shared-limiter progress, not completed real security scans. The consumer runs unprofiled for latency measurements; a separate initial analysis/refresh is cProfiled. Inclusive stage timers are reported without summing overlapping stages as exclusive CPU. Trade application age uses scheduled event time, so event-loop stalls cannot be hidden by assigning a later arrival timestamp.

Commands are bounded to <=600 seconds and <=100 trades/s; percentile buffers have a corresponding hard 60,000-event limit. JSON/profile outputs refuse overwrite. A three-second harness-development check processed 45/45 events at 250 candidates, with p99 application age 0.717s; it is not the sustained acceptance result.
