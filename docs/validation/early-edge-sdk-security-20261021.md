## Reachability and exploit conditions

Pump/PumpSwap SDK compiled entrypoints import Anchor → TOML, Solana SPL → buffer-layout-utils → bigint-buffer, and web3.js → jayson → UUID. This executes module initialization even though only quote helpers are called. Thus **high-severity affected packages are loaded**. That is not a clean SDK audit.

Instrumentation of the exact supplied-state quote path recorded no TOML parse calls, no bigint LE/BE conversion calls, and no UUID v3/v5/v6 calls in either venue. No bigint native addon was loaded; only bufferutil.node was loaded. `stream-json` was not loaded on this path. Static source corroborates: bigint-buffer catches missing native binding and selects its JS fallback; Anchor workspace TOML discovery, RPC clients/servers and stream parsers are unused by quote helpers. Dynamic coverage is bounded evidence, not a proof about every possible SDK function/input.

The high root advisories are native bigint-buffer overflow via hostile conversion buffers and TOML recursion/prototype pollution via hostile TOML text. Neither vulnerable operation was reached by the tested quote path. BN.js moderate-risk arithmetic **is reached** with reviewed bounded integer inputs; unknown strings, unbounded state and caller-selected radix/output buffers are not supplied. Streaming JSON exploits require invoking the streaming parser/filter/assembler; UUID issue requires specific hash-version calls and output buffer arguments. No package lifecycle/build command runs in the quote child.

Root patches: BN.js 5.2.3; stream-json 3.6.0; TOML 4.2.0 (covers both root TOML ranges); UUID 11.1.1. No fixed bigint-buffer release was established in this audit. npm suggests force-downgrading official SDKs for several transitive nodes; this was **not** applied. Overriding transitive packages could leave the official SDK version unchanged but changes the audited reference graph and needs a new lock/audit/parity review. Downgrading the SDK itself changes official provenance.
